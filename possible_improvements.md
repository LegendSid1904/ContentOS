# ContentOS AI — Possible Improvements & Future Considerations

> **Status:** Backlog — revisit after v1 MVP is shipped.
> These are not urgent but worth building properly when the time comes.

---

## 1. AI Cost Management

**Problem:** At ₹1999/mo with Claude API costs, margins are tight. A single long-form script generation can cost significant tokens. No visibility into cost-per-user or cost-per-module.

**What to build:**
- Token usage tracking per user/session/module (store in Supabase)
- Cost-per-user dashboard for admin view
- Prompt caching (Claude API prompt caching feature) — cache system prompts + brand kits, only send unique user input
- Usage alerts: warn users when they're approaching plan limits
- Background cost optimization: switch to Haiku for low-risk tasks (idea generation), reserve Sonnet for script writing

**Priority:** High (affects profitability)

---

## 2. Prompt Versioning System

**Problem:** Every module has a dedicated system prompt. As you iterate, you'll make tweaks. Without versioning, you can't tell if a change improved output quality or broke something.

**What to build:**
- Prompt registry in Supabase: `prompts(id, module, version, system_prompt, user_prompt_template, created_at, notes)`
- A/B prompt testing: route 10% of traffic to prompt variant B, compare output ratings
- Prompt rollback: one click to revert to a previous prompt version
- Prompt changelog: what changed, when, and why

**Priority:** Medium (increases as product matures)

---

## 3. Output Quality Feedback Loop

**Problem:** No mechanism to know if outputs are good or bad. Without data, prompt improvements are guesswork.

**What to build:**
- 👍/👎 buttons on every AI output block (persisted to Supabase)
- Implicit signals: did the user regenerate? edit inline? export? abandon?
- Quality dashboard: which modules have the lowest satisfaction scores
- Feedback-driven prompt tuning: flag low-rated outputs for manual review

**Priority:** Medium

---

## 4. Rate Limiting & Request Queue

**Problem:** When 10+ users hit an AI module simultaneously, Vercel serverless functions + Claude API can hit timeouts (60s Vercel limit, API rate limits).

**What to build:**
- Request queue via Trigger.dev: enqueue AI generation jobs, process sequentially or in controlled batches
- Backpressure handling: show "Your script is queued — estimated wait X seconds" instead of timeout errors
- Per-user rate limiting: max 3 concurrent generations per user
- Queue priority: paid users skip ahead of free users

**Priority:** High (blocks scaling)

---

## 5. Content Moderation & Guardrails

**Problem:** No input/output safety checks. Users could generate harmful scripts or competitor analysis with hallucinated facts.

**What to build:**
- Input moderation: block prompts requesting harmful/illegal content
- Output guardrails: Claude's built-in safety filters + post-generation content check
- AI disclaimer banners: "Generated by AI — verify facts before publishing" on every export
- Cited sources for competitor data: when Claude uses web search, include source URLs
- Hallucination disclaimer on competitor reports

**Priority:** High (legal risk)

---

## 6. Data Portability / Bulk Export

**Problem:** No way for users to export all their data. GDPR requires it. Users also want to leave or migrate.

**What to build:**
- "Export all my data" button in account settings
- Export format: ZIP with individual JSON files per project + PDFs of all outputs
- Include brand kit, swipe files, and project history
- Trigger.dev job for large exports (send download link via email)
- Scheduled auto-exports for Agency plan

**Priority:** Medium (GDPR compliance)

---

## 7. Global ⌘K Search

**Problem:** Design system mockup shows a search bar, but no implementation. With 8 modules, projects, saved outputs, and swipe files, users need cross-module search.

**What to build:**
- ⌘K / Ctrl+K command palette
- Search across: projects, saved scripts, carousels, swipe files, brand kits
- Quick actions: "New Script", "New Idea Batch", "Go to Module X"
- Keyboard navigation (arrow keys + Enter to select)
- Recent searches history

**Priority:** Medium (polish)

---

## 8. Hinglish / Regional Language Complexity

**Problem:** Listed as a one-toggle feature, but reliable Hinglish script generation requires significant prompt engineering + testing.

**What to build:**
- Dedicated Hinglish system prompts (different from English prompts — grammar, code-switching patterns)
- Test suite with Hinglish scripts across niches (finance, fitness, comedy, education)
- Consider adding Hindi (Devanagari) + Tamil + Telugu support alongside Hinglish
- Prompt examples: "Generate this script in Hinglish with 60% Hindi, 40% English mix, using casual Indian social media tone"

**Priority:** Low (important for India market, but complex)

---

## 9. User Analytics Dashboard

**Problem:** Growth Strategy module does a one-time audit, but there's no ongoing analytics showing users how their content performs across platforms.

**What to build:**
- Connect YouTube / Instagram / LinkedIn APIs to pull real performance data
- Dashboard: views, engagement rate, follower growth over time
- Content performance breakdown: which scripts/thumbnails/carousels performed best
- AI recommendations based on performance data: "Your educational scripts perform 2x better than entertainment — increase educational content to 60%"
- Exportable performance reports for Agency clients

**Priority:** Medium (differentiator vs competitors)

---

## 10. Template Library

**Problem:** New users land on an empty dashboard. Cold start problem — they don't know what to do or what's possible.

**What to build:**
- Pre-built example for each module:
  - Script Writer: "How I Built a 6-Figure Agency in 12 Months" (YouTube educational)
  - Carousel: "5 AI Tools Every Creator Needs" (10 slides)
  - Content Ideas: Example niche "Personal Finance India" with 30 ideas
- "Try with Example" button on every module page (auto-fills form with sample data)
- Template gallery on dashboard for new users

**Priority:** Medium (conversion/retention)

---

## 11. Canva API Risk Mitigation

**Problem:** Canva API may change, restrict, or deprecate endpoints. Over-investing in tight Canva integration creates fragility.

**What to build:**
- Phase 1: Skip deep Canva API integration. Use Canva template links + downloadable PNG/PDF instead.
- Phase 2 (after Canva API stability is proven): Implement full Canva Connect API for in-app template editing.
- Always maintain the PNG/PDF fallback path as primary — Canva stays as optional enhancement.

**Priority:** Low (architectural decision)

---

## 12. Pricing & Free Tier Tuning

**Problem:** Free tier (5 scripts/month) may be too restrictive for conversion. Users need to feel the value before upgrading.

**What to tweak:**
- Consider: 10 scripts + 3 carousels + 5 thumbnail briefs on free (instead of just 5 scripts)
- Add a "try once with premium" button — free users can generate 1 premium output (full 90-day strategy)
- Usage reset: monthly, not rolling — so users don't feel penalized for joining mid-month
- Agency plan: consider usage-based add-ons for heavy clients

**Priority:** Medium (revenue optimization)

---

## 13. Remotion.dev — Programmatic Video Editing

**Not a v1 feature.** Keep this on ice for when Module 2 (Video Editing) matures into actual video rendering.

**Why Remotion:**
- Write videos in React — same stack as the rest of ContentOS
- Programmatic caption overlays (burn in the AI-generated captions directly)
- Dynamic B-roll insertion using stock footage APIs (Pexels/Pixabay)
- Template-based video generation: "Brand kit → 30 sec Reel with captions + stock footage + CTA"
- Can generate videos server-side (Node.js) and serve via Supabase Storage / R2

**When to build:**
- Wait until Module 2 (Editing Briefs) is stable and users are exporting briefs
- Once demand is proven, start with automated caption videos (lowest effort, highest value)
- Then add B-roll assembly, then full template-based video generation

**What you'll need:**
- Remotion license (commercial) — required for revenue-generating use
- Pexels/Pixabay API key for stock footage
- FFmpeg installed on server (for rendering)
- Trigger.dev long-running job (Remotion renders can take 2-10 minutes)
- Consider: Remotion Lambda for scalable rendering (more expensive but faster)

**Architecture sketch (future):**
```
User uploads transcript / script
  → Editing Brief generated (AI)
  → User selects caption style + B-roll keywords
  → Remotion composition assembled (React code on server)
  → Rendered via Remotion Lambda or local FFmpeg
  → Video uploaded to Supabase Storage / R2
  → User gets download link + preview
```
